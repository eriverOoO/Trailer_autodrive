# 주차 구현 검증 기록 — 2026-09-16

## 전달 상태

전후방 카메라를 사용하는 두 ROS 2 실행 구성을 구현했다.

- `parallel_lidar_yolo.launch.py`: 전후방 YOLO + 두 LaserScan의 장애물 영역 융합.
- `parallel_camera_yolo.launch.py`: 전후방 YOLO + 지면 영상 이동 추정. LiDAR 및
  Gazebo 정답 위치/연결각 토픽을 구독하지 않는다.

**완성된 자율주차 시스템이 아니라, 실행 구성과 알고리즘을 갖춘 실험용 초안이다.**
아래 실패 항목을 해결하기 전에는 실제 차량이나 Gazebo 주차 성공을 주장할 수 없다.

## 확인한 사항

- Ubuntu 22.04 / ROS 2 Humble에서 새 패키지의 `colcon build` 성공.
- 운동학, 전체 차량 목표 판정, 장애물 충돌, 카메라 투영, 합성 영상 이동 추정,
  LaserScan 각도 처리, 센서 freshness, 카메라 전용 구독, 연결부 위치 불일치,
  LiDAR 누락 등 테스트 17개 통과.
- 새 Python 파일과 도구 21개 문법 검사 통과.
- 현재 `best.pt` 메타데이터에서 segment task 및
  `parking_space`, `car_front`, `car_back` 클래스 확인. 실제 추론 정확도는 미측정.

## 수치 실험 결과와 한계

모든 아래 실험은 이상적인 운동학과 정확한 상태 입력을 사용한다.
실제 카메라 영상/YOLO/Gazebo 물리 엔진을 연결한 실험이 아니다.
칸 너비 3.2m는 실험용 가정이다.

| 조건 | 경로 생성 | 추종 완료 | 해석 |
|---|---|---|---|
| 11.094831m 길이, 시작 (9,-4), 연결각 제한 40° | 시간 내 실패 | 미실행 | 기존 빈 간격에서 성공 확인 못함 |
| 14m 길이, 시작 (9,-4), 제한 40° | 성공 | 성공 | 범퍼 간섭 검토 전 실험. 최종 유효 성공으로 취급하지 않음 |
| 14m 길이, 시작 (12,-3.2), **최종 제한 20°** | 성공, 약 12.1초 | **실패** | 최대 연결각 18.43°, 경로 225점. 12,000 tick 내 목표 미도달 |

마지막 실험은 외부 장애물 충돌 없이 경로를 만들었지만 추종이 완료되지 않았다.
추종기의 짧은 방향 전환 구간 처리와 연결각 피드백 튜닝이 우선 남은 작업이다.
11.1m 공간에서 경로를 못 찾았다는 것은 수학적으로 주차가 불가능하다는 증명이
아니며, 현재 탐색/최적화 방식과 시간 예산의 한계다.

원본 힌지는 ±45°를 허용하지만, SDF의 견인차 뒷범퍼와 트레일러 앞범퍼를
평면에서 비교하면 20°에서는 분리되고 25° 이상에서는 겹쳤다.
이에 기본 운용 연결각 제한을 20°로 낮췄다. 전체 메시 충돌/타이어 동역학을
검증한 결과는 아니며, 실물 치수와 다른 연결부에서는 다시 계산해야 한다.

## 다음 작업 우선순위

1. 마지막 수치 경로의 방향 전환 구간을 추적해 추종 미완료 원인을 수정.
2. 최종 20° 제한에서 실제 네 시작점과 11.1m 공간에 대한 경로 생성/추종 검증.
3. Gazebo 의존성과 YOLO 런타임 설치 후 영상 토픽, 시야, 추론 지연 확인.
4. 전후방 시점에서 충분한 지면 특징점과 완전한 주차칸 마스크가 확보되는지 확인.
5. 실차 전후방 데이터 라벨링, 추가 학습 및 평가. 이번 작업에서 새 학습은 하지 않음.

재현 명령과 실행 방법은 저장소 `README.md`에 있다.
