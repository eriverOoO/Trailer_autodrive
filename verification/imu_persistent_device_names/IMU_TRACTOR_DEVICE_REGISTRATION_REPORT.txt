2. 식별 방법 분석 / 설치 보류 이유
과거 실제 G6 성공 기록 verification/g6_12hz/udev.txt와 lidar_hardware.log를 조사.
G6에도 VID/PID, serial0001, ID_SERIAL, interface00, revision0100이 동일하며 당시 ID_PATH까지 현재와 동일.
단순 serial 또는 전체 제품명으로 두 역할을 구분할 수 없음.
현재 연결 장치는 사용자 확인과 실제 EBIMU 패킷으로 식별했지만, 그 USB 정보 자체가 역할 고유값은 아님.
EEPROM이나 USB serial을 변경하지 않고, G6 UART를 자동 점유하는 udev PROGRAM도 사용하지 않음.
대안 후보는 ID_PATH를 포함한 '전용 USB 소켓' 규칙.
이것도 센서 고유 식별이 아니며 지정 소켓에 G6를 꽂으면 G6도 매칭함.
따라서 현재 소켓을 트랙터 전용으로 사용할지, 다른 소켓을 지정할지, 설치 보류할지 사용자에게 질문한 상태.
이 선택을 받기 전에는 안전 조건이 확정되지 않아 /etc에 설치하지 않음.

3. USB 포트 변경 시
현재 정보로 USB 소켓과 무관한 안전한 역할 자동 식별은 불가능.
후보는 현재 USB 소켓에서 ttyUSB 번호가 달라져도 /dev/imu_tractor를 만드는 역할 매핑.
다른 소켓으로 옮기면 후보의 ID_PATH와 달라져 별칭이 만들어지지 않음.
'어느 USB 포트에서도 같은 이름으로 인식'을 달성했다고 주장하지 않음.
아직 연결하지 않은 트레일러 IMU의 serial 고유성도 미검증.
