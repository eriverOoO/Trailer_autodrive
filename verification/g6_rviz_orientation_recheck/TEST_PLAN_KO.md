# 재진단 시험 계획 — 아직 실행하지 않음

## 시작 조건

사용자가 G6 본체를 고정했고, 기준 측정에서는 시험용 판을 두지 않았다고 확인해야 한다. 현재 이 확인을 기다리는 중이다. 확인이 없으면 센서 드라이버 및 Cartographer를 실행하지 않는다.

## 새 세션

기존 프로젝트 프로세스를 종료하지 않는다. 다른 G6/Cartographer가 이미 실행 중이라면 소유 관계와 토픽 충돌을 확인하고 진행을 보류한다. 이번 세션은 기존 g6_slam.launch.py의 sensor 모드, use_imu=false, 기존 YAML/Lua 및 최근 사용한 g6_front_up.rviz를 그대로 실행한다. load_state_filename 등 저장 상태 입력을 넣지 않는다. 실행 인자와 프로세스 목록을 저장한다. ROS 로그 위치만 이번 진단 폴더 아래로 지정한다.

## 정지 기준

새 trajectory 0 시작 및 첫 스캔 처리 확인 후 70초 관찰한다. 최초 5초는 버퍼 워밍업으로 따로 보고하고 나머지 구간에서 실제 스캔 첫/마지막 수신 간격이 60초 이상인지 확인한다. 실제 고정 여부는 사용자 확인으로 기록하며 추정 위치가 안정적이라는 이유만으로 물리적 고정을 추론하지 않는다.

수집: 원시 LaserScan, 유효/무효 거리, 실제 수신 주파수, 획득 시각/끝 시각, scan-matched cloud 수신 빈도, OccupancyGrid와 Submap 갱신, 동적/정적 TF 부모/자식 및 RPY, map→laser_frame 추정 XY/yaw 변동, 모든 경고/오류. map→laser_frame yaw 차이는 센서 케이블 오프셋과 구분한다.

## 화면 비교

기존 RViz 파일에 저장하지 않는다. 실제 런타임 Display 종류·토픽·QoS·색 변환·Alpha·Decay·크기·큐·Status를 조사한다. 원래 표시 상태 → Scan만 → Map만 → 둘 동시 → 원래 상태 순서로 캡처한다. 이전 진단에서 LaserScan 재활성화 이후 TF 오류가 재현됐으므로 전후 시간을 기록하며, 이 조작에서 생긴 현상을 처음부터 있던 문제로 분류하지 않는다. 파일로 런타임 구성을 기록한다면 이 폴더 안에 새 이름으로 저장한다.

## 물리 표적 단계 — 각 단계마다 확인 대기

1. 고정 상태·표적 없음: 기준 스캔/지도 기록.
2. 사용자에게 스캔 높이를 가로지르는 판을 케이블 전방 약 1m에 배치하도록 요청하고 완료 확인을 기다림.
3. 센서가 움직이지 않았다는 확인과 함께 표적 설치 상태를 기록.
4. 사용자에게 판만 제거하도록 요청하고 완료 확인을 기다림.
5. 제거 후 기록. 전방 근거리 반사점 소멸과 후방 배경 반사점 출현을 각도/거리 수치로 구분.
6. 가능한 경우 후방/좌측/우측도 각 배치 완료 확인 후 기록. 실측 방향과 ROS 측정각의 차이를 계산. 미확인 배치는 성공으로 기록하지 않음.

## 종료 및 보존

이번 작업에서 시작한 프로세스만 종료한다. 기존 파일 SHA256를 다시 비교한다. 기존 성공 지도, PBStream, 로그는 삭제/덮어쓰기 하지 않는다. 코드/설정 변경 없이 결과와 미확정 항목을 G6_RVIZ_ORIENTATION_RECHECK_REPORT.md에 기록한다. 추가 수정은 별도 지시까지 수행하지 않는다.
