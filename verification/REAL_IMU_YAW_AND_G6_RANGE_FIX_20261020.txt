2. 기존 Yaw 반전 원인 조사
현재 경로: serial_protocol.Parser (제조사 z,y,x,w -> ROS x,y,z,w) -> serial_bridge 실제 Imu Quaternion -> visualizer.YawTrack -> render_adapter.
제조사 EBIMU 매뉴얼 Quaternion 순서와 파서 매핑 일치. 공용 IMU 메시지는 변경하지 않음.
수정 전 트랙터 설정 sign=1이 시각화 내부 Yaw에 한 번 적용됐음. 초기 기준은 상수 offset이며 이후 delta의 부호를 바꾸지 않음.
row-vector 변환 p @ [[cos,sin],[-sin,cos]]와 Marker Quaternion sin(yaw/2)/cos(yaw/2)는 ROS +Yaw(CCW)와 일치.
카메라 TopDownOrtho/Angle0이며 지도·Scan·카메라 반전은 하지 않음.
사용자가 실제 장착 상태의 CCW 수동 회전을 완료했다고 확인함. 기록상 raw Yaw와 화면 Yaw가 함께 감소하여 역방향 재현. sign=+1이 네이티브 회전 방향을 그대로 통과시킨 것이 시각화 원인.
첫 CCW 기록을 근거로 진단 sign=-1을 적용했으나, 이후 CW 복귀 기록과 일치하지 않아 이 부호의 물리적 최종 판정은 보류한다.
CW 복귀 구간 raw=-9.350도, arrow=+9.354도, hull=+9.377도로 기록되었고 Pitch가 약-5도에서-28도로 변했다. 수평 회전과 기울기 변화가 섞여 재시험 요청.
센서 축/장착 기울기 또는 제조사 자세 기준의 물리적 세부 원인은 미교정이며, 각도 크기 정확도를 확정하지 않음.

5. 기존 거리 1m 제한 원인
기존 src/mvsim_slam_real_bringup/config/g6.yaml range_max=1.0이 SDK LidarPropMaxRange -> m_MaxRange로 전달됨.
SDK isRangeValid가 범위 밖을 0으로 처리하고 드라이버 LaserScan은 SDK min/max를 그대로 사용함.
active g6_lidar_only.lua는 reference_lidar_only.lua를 include한 뒤 max_range=1.0으로 최종 override.
RViz 시점 문제가 아니라 실제 드라이버/Cartographer 양쪽 제한이었음. baseline runtime dump/scan 기록으로 확인.

6. 거리 설정 전후 및 경계
변경 전: G6 0.15~1.0m, Cartographer 0.15~1.0m. 실제 baseline Scan 11.62900585067365Hz.
변경 후: G6 range_min=0.15, range_max=12.0m; Cartographer min_range=.15/max_range=12.0.
SDK 경계는 reading>=m_MinRange && reading<=m_MaxRange, Cartographer도 range>=min && range<=max로 양 끝 포함.
float32 LaserScan range_min 표시는 약0.15000000596m. 최소 field와 실제 장치 정확도는 별개.
missing_data_ray_length=1.0m는 그대로 유지: 유효 hit의 최대 거리와 별개인 초과 hit의 free-space miss 길이. 무조건12m로 늘려 빈 공간을 길게 지우지 않음.
현재 드라이버가 12m 초과를 SDK에서0으로 버리므로 가짜12m 장애물을 생성하지 않음. Cartographer min_range가0도 배제.
보존: 512000baud/18K/12Hz/laser_frame/inverted=true/reversion=false/장치by-path/기타센서파라미터.
거리 외 Cartographer 알고리즘/LiDAR-only 모드 변경 없음.
